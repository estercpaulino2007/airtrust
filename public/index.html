Environmental events

Events are created by the reasoning layer when AI anomalies, nearby sensors and citizen reports agree. Verified events are hashed with SHA-256 and anchored on-chain.

Citizen signal network

Residents report what they see, smell or feel. The AI correlates each report with nearby sensors using distance, timing, pollutant increase, wind direction and neighbour confirmation. Locations are rounded to ~110 m for privacy; no contact data is stored with the report.

Trust ledger

Only cryptographic fingerprints go on-chain, never raw data. Routine readings are grouped into Merkle batches (one transaction covers hundreds of readings, each still individually provable). Verified events and their peak readings get their own proofs.

Public verification portal

Anyone can check that a reading or event was not altered after it was recorded. The portal recomputes the SHA-256 hash from the stored data and asks the smart contract whether that exact fingerprint was anchored.

    Evidence
    Run a verification to see the canonical payload, hashes and the on-chain proof.
    Integrity-failure demonstration (admin)

    Simulates an attacker with database access silently editing the stored record. The on-chain proof cannot be changed, so verification fails.

    Scenario simulator

    Inject controlled events into the simulated sensor mesh and watch the AI react on the command center. Requires an operator or admin session.

    Research API & open data

    Every reading carries its AI status, confidence score and integrity proof, so researchers can choose between raw data and AI-trusted "official" data, and verify any record independently.
